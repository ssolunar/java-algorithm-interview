### P1. 유효한 팰린드롬

- **난이도** ★ | [문제 링크](https://leetcode.com/problems/valid-palindrome/) | 책 풀이: [P1_1.java](../../src/ch06/P1_1.java) · [P1_2.java](../../src/ch06/P1_2.java) · [P1_3.kt](../../src/ch06/P1_3.kt) | 내 풀이: [P1.java](solutions/P1.java)
- **첫 시도** ⬜ 자력 해결 / ✅ 힌트 후 해결 / ⬜ 책 참고
- **접근**
  - 정규식으로 영숫자만 남기고 소문자로 변환: `s.replaceAll("[^a-zA-Z0-9]", "").toLowerCase()`
  - 앞 절반만 돌면서 `i`번째와 `len - i - 1`번째 문자를 비교, 하나라도 다르면 `false`
- **복잡도** 시간 `O(n)` / 공간 `O(n)` (전처리한 문자열을 새로 만들기 때문)
- **내 풀이 vs 책 풀이**

  | | 내 풀이 | 풀이 1 (P1_1, 투 포인터) | 풀이 2 (P1_2, 뒤집기) |
  | --- | --- | --- | --- |
  | 전처리 | `replaceAll` 정규식 | 없음 (그 자리에서 건너뜀) | `replaceAll` 정규식 |
  | 비교 | 인덱스로 양 끝 비교 | `start`/`end` 포인터 | `StringBuilder.reverse()` 후 `equals` |
  | 추가 공간 | O(n) | **O(1)** | O(n) |

  - 내 풀이는 풀이 2의 전처리와 풀이 1의 비교 방식을 섞은 형태.
  - 풀이 1은 새 문자열을 만들지 않고 원본 위에서 `Character.isLetterOrDigit()`로 건너뛰며 비교해서 가장 빠르다.
    - `isLetterOrDigit()`는 한글 같은 유니코드 문자도 `true`라서 `[A-Za-z0-9]`와 완전히 같지는 않음. 이 문제는 ASCII 입력이라 차이 없음.
  - 풀이 2는 코드가 가장 짧다.
  - `if (s.equals(" ")) return true;`는 불필요했다. 공백만 있는 입력은 전처리 후 `""`가 되고 반복문이 안 돌아서 어차피 `true`.
  - `if (같으면) continue; else return false;` → `if (다르면) return false;` 한 줄이면 충분.
- **막혔던 점**
  - `for`를 써야 할 자리에 `if (int i = 0; ...)`라고 써서 컴파일 에러. `if` 괄호 안에는 조건식 하나만 올 수 있다.
  - `replace("[^a-zA-Z]", "")`가 아무것도 안 지웠다. **`replace`는 정규식이 아니라 문자 그대로를 찾는다.**
    - 두 메서드 모두 일치하는 부분을 **전부** 바꾼다. 차이는 첫 인자를 정규식으로 보느냐 문자 그대로 보느냐.
    - 정규식을 받는 String 메서드: `replaceAll`, `replaceFirst`, `matches`, `split` (파라미터 이름이 `regex`)
    - `split(".")`, `split("|")` 함정. 정규식 기호라서 `split("\\.")`처럼 이스케이프해야 한다.
  - 처음엔 알파벳만 남겼는데 문제 조건은 **영숫자(alphanumeric)**. `"0P"` 같은 입력에서 틀린다.
  - 인덱스를 `len - i`로 써서 범위를 벗어남. 마지막 인덱스는 `len - 1`이므로 `len - i - 1`.
- **더 알게 된 것: StringBuilder는 스레드 안전하지 않다**
  - 여러 스레드가 같은 `StringBuilder`에 동시에 `append()`하면 글자가 덮어써지거나 예외가 날 수 있음 (경쟁 상태).
  - 스레드 안전한 버전은 `StringBuffer` (메서드에 `synchronized`). 대신 동기화 비용 때문에 약간 느림.
  - 코딩테스트나 지역 변수처럼 스레드 하나만 쓰는 경우엔 `StringBuilder`가 맞다.

### P2. 문자열 뒤집기

- **난이도** ★ | [문제 링크](https://leetcode.com/problems/reverse-string/) | 책 풀이: [P2_1.java](../../src/ch06/P2_1.java) · [P2_2.kt](../../src/ch06/P2_2.kt) | 내 풀이: [P2.java](solutions/P2.java)
- **첫 시도** ✅ 자력 해결 / ⬜ 힌트 후 해결 / ⬜ 책 참고
- **접근**
  - 투 포인터 + swap. `start = 0`, `end = s.length - 1`에서 시작해 양 끝을 임시 변수 `tmp`로 맞바꾸고 안쪽으로 한 칸씩 좁힌다.
  - `start < end` 조건이라 길이가 홀수면 가운데 문자는 안 건드리고, 길이 1이면 반복문이 안 돈다.
- **복잡도** 시간 `O(n)` (교환 n/2번) / 공간 `O(1)` (`start`, `end`, `tmp` 변수 3개)
- **내 풀이 vs 책 풀이**
  - 책 풀이 P2_1과 사실상 같은 코드. P1 책 풀이에서 본 투 포인터를 바로 써먹었다.
  - Kotlin 풀이 P2_2는 `s[start] = s[end].also { s[end] = s[start] }`로 임시 변수 없이 한 줄 swap.
    1. `s[end]` 값을 먼저 꺼내 둔다.
    2. `also` 블록에서 `s[end]`에 `s[start]`를 넣는다.
    3. 꺼내 둔 원래 `s[end]` 값이 `s[start]`에 대입된다.
    - 자바엔 이런 문법이 없어서 임시 변수가 표준.
- **막혔던 점**
  - 없음. 대신 문제 조건 문장을 정리했다.
- **더 알게 된 것: in-place, O(1) extra memory**
  - `You must do this by modifying the input array in-place with O(1) extra memory.`
  - **in-place**: 새 배열에 결과를 만들지 말고, 받은 배열 `s` 자체를 고친다.
  - **O(1) extra memory**: n이 커져도 추가로 쓰는 메모리 양이 일정해야 한다. 입력 배열 자체는 "extra"에 포함 안 됨.

    | 코드 | 추가 메모리 |
    | --- | :---: |
    | `start`, `end`, `tmp` 변수만 사용 | O(1) |
    | `new char[n]`에 뒤집어 담기 | O(n) |
    | `new StringBuilder(...).reverse()` | O(n) |

  - **반환값이 `void`인데 답이 전달되는 이유**: 배열은 참조형이라 메서드는 배열 객체의 주소를 받는다. 그 주소로 찾아가 내용을 바꾸면 호출한 쪽의 원본 배열이 바뀐다. LeetCode는 함수가 끝난 뒤 원본 배열을 확인해서 채점한다.
    - 4장 원시형 vs 참조형과 이어지는 내용. 책 예제 [CallByValueExample.java](../../src/ch06/CallByValueExample.java)가 같은 동작(넘겨받은 리스트에 `add`하면 원본이 바뀜)을 보여준다.
