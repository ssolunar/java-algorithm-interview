### P7. 두 수의 합

- **난이도** ★ | [문제 링크](https://leetcode.com/problems/two-sum/) | 책 풀이: [P7_1.java](../../src/ch07/P7_1.java) · [P7_2.java](../../src/ch07/P7_2.java) · [P7_3.java](../../src/ch07/P7_3.java) · [P7_4.java](../../src/ch07/P7_4.java) · [P7_5.kt](../../src/ch07/P7_5.kt) | 내 풀이: [P7.java](solutions/P7.java) · 첫 시도: [P7_v1.java](solutions/P7_v1.java) (재귀 조합) · [P7_v2.java](solutions/P7_v2.java) (이중 for문)
- **첫 시도** ⬜ 자력 해결 / ✅ 힌트 후 해결 / ⬜ 책 참고
- **접근**
  - `nums[i]`의 짝은 **`target - nums[i]`로 이미 정해져 있다.** "짝이 있나?"를 `O(1)`에 알면 전체가 `O(n)`.
  - `HashMap<숫자, 인덱스>`에 전부 넣고, 다시 돌면서 `map.containsKey(target - nums[i])` 확인. 답이 인덱스라서 `Set`이 아니라 `Map`.
  - 자기 자신과 짝지어지는 경우(`[3, 3]`, target 6에서 `i=1`이 자기 자신을 찾음)는 `map.get(r) != i`로 막는다.
  - 같은 숫자는 맵에서 덮어써져 **마지막 인덱스**만 남는다. 앞에서부터 도는 `i`가 첫 번째 것을 볼 때 뒤의 것을 찾으니 문제없다.
- **복잡도** 시간 `O(n)` / 공간 `O(n)` (맵)
- **내 풀이 vs 책 풀이**

  | 풀이 | 방법 | 시간 | 결과 |
  | --- | --- | :---: | --- |
  | 내 첫 시도 (P7_v1) | 재귀 조합으로 2개 고르기 + 매번 배열 전체로 합 계산 | `O(n³)` | 시간 초과 |
  | 내 두 번째 (P7_v2) = 책 P7_1 | 이중 for문 | `O(n²)` | 통과 (느림) |
  | **내 풀이 (P7) = 책 P7_2** | 맵 채우기 → 짝 찾기 (반복문 2개) | `O(n)` | 통과 |
  | 책 P7_3 | 반복문 1개: 짝이 앞에 있나 확인 → 없으면 자기를 넣기 | `O(n)` | — |
  | 책 P7_4 | 양 끝 투 포인터 | — | **이 문제엔 틀림** |

  - P7_v1이 느렸던 이유: 확인하는 쌍은 P7_1과 같은데, 쌍마다 실제로 더하는 건 2개뿐이면서 `visited` 배열 **전체(n개)**를 훑었다. 재귀 호출 비용도 반복문보다 크다.
    - **조합 백트래킹은 고를 개수가 입력마다 달라질 때 쓰는 도구.** 개수가 정해져 있으면(2개) for문을 그만큼 겹쳐 쓰는 게 간단하고 빠르다.
  - **P7_3 (한 번 순회)**: 자기를 넣기 **전에** 확인하므로 자기 자신과 짝지어질 일이 없어서 `!= i` 조건이 필요 없다. 정답 쌍 중 뒤의 숫자를 볼 때 앞의 숫자는 이미 맵에 있으니 반드시 찾는다.
  - **P7_4 (투 포인터)**: 합이 작으면 `left++`, 크면 `right--`. 배열이 **정렬되어 있어야** 동작하는데, 이 문제 입력은 정렬되어 있지 않다(`[3, 2, 4]`). 정렬하면 원래 인덱스가 바뀌어서 인덱스를 반환하는 이 문제엔 바로 못 쓴다. → P9 세 수의 합에서 제대로 쓰임.
  - `map.get(r) != i`: `Integer`와 `int` 비교라 자동 언박싱돼서 값으로 비교된다. (`Integer`끼리 `!=`/`==`는 객체 비교라 주의)
- **막혔던 점**
  - **재귀에서 찾은 답이 위로 전달되지 않음** (P7_v1)
    - 재귀 호출의 반환값을 받지 않고 버림 → 맨 위 호출은 항상 `null` → `NullPointerException`.
    - `void`로 바꾸니 `[0, 0]`. 깊은 곳에서 `return`해도 **자기 호출 하나만** 끝나고, 위 호출로 돌아가면 `visited[i] = false`가 답 표시를 지우고 탐색을 계속한다.
    - 해결: `boolean`을 반환해서 `if (combination(...)) return true;`로 "찾았다" 신호를 위로 전달. 되돌리기 **전에** 반환해야 한다.
    - `r == 0`인데 합이 다르면 아래 for문으로 내려가 3개, 4개를 계속 고름. `r == 0`이면 맞든 틀리든 그 자리에서 `return`.
  - **찾아도 멈추지 않음**: `ans`에 저장만 하고 계속 돌아서 뒤의 결과(자기 자신과의 짝)가 정답을 덮어씀 → `[3, 3]`에서 `[1, 1]`.
  - **`return`을 `if` 밖에 둠**: `i=0`에서 찾든 못 찾든 바로 반환 → `[3, 2, 4]`에서 초기값 `[0, 0]`. `[3, 3]`은 `i=0`에서 정답이 나와서 이 실수가 안 보였다. **반복문 안의 `return`은 조건 안에 있는지 확인.**
  - 깨달은 것: **"짝이 있나?" 같은 존재 확인을 반복하면 해시로 바꾼다.** (P4 `HashSet`, P5 `HashMap`, P7 `HashMap`)
